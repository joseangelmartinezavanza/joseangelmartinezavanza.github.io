4. Directivas y módulos de Apache

En los apartados anteriores ya hemos utilizado instrucciones como Listen, DocumentRoot, ServerName o DirectoryIndex.

Esas instrucciones no son comandos de Linux: son directivas de configuración de Apache.

Además, Apache tiene una arquitectura modular. Algunas funciones forman parte del núcleo del servidor y otras son proporcionadas por módulos que pueden estar habilitados o no.

En este apartado aprenderemos a reconocer ambos conceptos y, sobre todo, a consultar la documentación para saber cómo debe utilizarse una directiva.

Idea clave

No necesitamos memorizar todas las directivas de Apache.

Debemos saber:

  1. Qué función realiza una directiva.
  2. En qué lugar puede utilizarse.
  3. Qué módulo la proporciona.
  4. Cómo comprobar si ese módulo está disponible.
  5. Cómo consultar la documentación oficial cuando aparezca una directiva que no conocemos.
¿Para qué nos sirve este apartado?

A partir de ahora aparecerán directivas que todavía no conocemos y funcionalidades que dependen de módulos concretos.

El objetivo no es memorizar todas las directivas de Apache, sino saber:

qué necesitamos hacer → qué directiva puede resolverlo → dónde puede utilizarse → qué módulo la proporciona → cómo comprobar que Apache puede usarla

Este procedimiento nos permitirá configurar Apache con más autonomía y, sobre todo, entender mejor los errores cuando una configuración no funciona.

4.1. Qué es una directiva​

Una directiva es una instrucción que modifica algún aspecto del comportamiento de Apache.

Ya hemos utilizado varias:

DirectivaPara qué la hemos utilizado
ListenIndicar en qué puerto debe escuchar Apache.
DocumentRootEstablecer el directorio que contiene un sitio web.
ServerNameIndicar el nombre principal de un host virtual.
ServerAliasAñadir nombres alternativos a un host virtual.
ErrorLogIndicar dónde se almacenan determinados errores.
CustomLogConfigurar el registro de accesos.

Por ejemplo:

Listen 8081

indica que Apache debe aceptar conexiones en el puerto 8081.

Y:

DocumentRoot /var/www/empresa1

indica qué directorio contiene los recursos que debe servir un sitio.

en este ejemplo

La primera palabra identifica la directiva.

Lo que aparece después son los argumentos de esa directiva.

Cada directiva tiene su propia sintaxis y no todas admiten los mismos valores.

4.2. El lugar donde aparece una directiva importa​

Una directiva no puede utilizarse necesariamente en cualquier parte de la configuración.

Apache distingue distintos contextos.

Los que más nos interesan durante esta unidad son:

ContextoDónde aparece
Configuración del servidorEn los archivos generales de configuración de Apache.
Host virtualDentro de un bloque <VirtualHost>.
DirectorioDentro de un bloque <Directory>.
.htaccessEn un archivo .htaccess, si el servidor permite utilizar esa directiva allí.

Por ejemplo:

<VirtualHost *:80>
    ServerName www.empresa1.test
    DocumentRoot /var/www/empresa1
</VirtualHost>

ServerName y DocumentRoot se están utilizando dentro del contexto de un host virtual.

También podemos aplicar algunas directivas a un directorio concreto:

<Directory /var/www/empresa1>
    Options -Indexes
    DirectoryIndex bienvenida.html
</Directory>
en este ejemplo

El bloque <Directory> agrupa instrucciones que deben aplicarse al directorio indicado.

En este ejemplo:

  • Options -Indexes evita que Apache muestre automáticamente el contenido del directorio.
  • DirectoryIndex bienvenida.html indica que bienvenida.html será uno de los recursos que Apache buscará cuando se solicite ese directorio.
No copies una directiva en cualquier lugar

Que una directiva exista no significa que podamos escribirla en cualquier archivo o contexto.

Antes de utilizar una directiva que no conocemos debemos consultar su documentación y comprobar el apartado Context.

4.3. Cómo consultar una directiva​

La documentación oficial de Apache incluye un índice con las directivas disponibles:

Índice de directivas de Apache HTTP Server 2.4

No utilizaremos ese índice como una lista para memorizar. Lo utilizaremos como herramienta de consulta.

Vamos a fijarnos en DirectoryIndex, una directiva que utilizaremos en nuestras prácticas.

Su documentación aparece dentro del módulo mod_dir:

Directiva DirectoryIndex

Directivas que debemos conocer

No necesitamos estudiar todas las directivas de Apache.

Durante la unidad iremos seleccionando las directivas que necesitamos para cada configuración. Cuando aparezca una directiva nueva, podemos localizarla en la documentación oficial de Apache y comprobar su función, sintaxis, contexto y módulo.

Al consultar una directiva encontraremos información como esta:

CampoQué debemos comprobar
DescriptionQué hace la directiva.
SyntaxCómo debe escribirse.
DefaultQué valor utiliza Apache si no indicamos otro.
ContextEn qué lugares puede utilizarse.
OverrideQué permiso necesita para poder utilizarse desde .htaccess.
StatusCómo se clasifica la funcionalidad dentro de Apache.
ModuleQué módulo proporciona la directiva.

Para DirectoryIndex, la documentación nos indica que pertenece a:

mod_dir

y que puede utilizarse en varios contextos, entre ellos:

  • Configuración del servidor.
  • Host virtual.
  • Directorio.
  • .htaccess.
Cuando aparezca una directiva nueva

No busques únicamente un ejemplo para copiar.

Comprueba primero:

qué hace → cómo se escribe → dónde puede utilizarse → qué módulo la proporciona

Ese procedimiento nos permitirá resolver buena parte de los ejercicios de configuración de Apache.

4.4. Aplicar directivas y comprobar su efecto​

Vamos a utilizar dos directivas sencillas sobre el sitio empresa1 que ya tenemos configurado.

Queremos comprobar qué cambia realmente cuando modificamos la configuración de Apache.

Trabajaremos con:

  • Options -Indexes.
  • DirectoryIndex.

Primera comprobación: impedir el listado del directorio​

Supongamos que dentro de:

/var/www/empresa1/

tenemos varios archivos, pero temporalmente no existe ningún archivo de inicio válido como index.html.

Podemos comprobar el contenido con:

ls -l /var/www/empresa1/

Abrimos el archivo de configuración del host virtual:

sudo nano /etc/apache2/sites-available/empresa1.conf

Añadimos un bloque <Directory>:

<VirtualHost *:80>
    ServerName www.empresa1.test
    DocumentRoot /var/www/empresa1

    <Directory /var/www/empresa1>
        Options -Indexes
    </Directory>
</VirtualHost>
en este ejemplo

Options -Indexes desactiva la generación automática de un listado del contenido de un directorio cuando no existe un recurso de índice válido.

Lo importante en esta primera prueba es observar el efecto de la directiva: el contenido existe, pero Apache no muestra una lista navegable de los archivos.

Comprobamos la configuración:

sudo apache2ctl configtest

Si obtenemos:

Syntax OK

recargamos Apache:

sudo systemctl reload apache2

Ahora accedemos a:

http://www.empresa1.test

Apache no debería mostrar automáticamente la lista de archivos del directorio.

El resultado puede ser un error 403

Si no existe una página de inicio válida y el listado del directorio está desactivado, Apache puede responder con 403 Forbidden.

En esta práctica ese resultado es coherente con lo que estamos configurando: hemos indicado que no queremos que muestre el contenido del directorio.

Segunda comprobación: elegir la página de inicio​

Creamos ahora un archivo:

sudo nano /var/www/empresa1/bienvenida.html

Podemos utilizar un contenido sencillo:

<h1>Bienvenida a Empresa 1</h1>
<p>Página de inicio configurada mediante DirectoryIndex.</p>

Volvemos al archivo:

sudo nano /etc/apache2/sites-available/empresa1.conf

Y añadimos:

<VirtualHost *:80>
    ServerName www.empresa1.test
    DocumentRoot /var/www/empresa1

    <Directory /var/www/empresa1>
        Options -Indexes
        DirectoryIndex bienvenida.html
    </Directory>
</VirtualHost>
en este ejemplo

DirectoryIndex bienvenida.html indica qué recurso debe intentar servir Apache cuando el cliente solicita el directorio.

Las dos directivas se aplican únicamente al directorio indicado porque se encuentran dentro del bloque <Directory>.

De esta forma hemos podido observar por separado:

  • Options -Indexes → evita que Apache liste el contenido del directorio.
  • DirectoryIndex bienvenida.html → indica qué archivo debe utilizar como página de inicio.

Comprobamos y recargamos:

sudo apache2ctl configtest
sudo systemctl reload apache2

Accedemos de nuevo a:

http://www.empresa1.test

Ahora Apache debería servir automáticamente bienvenida.html.

Comprueba siempre antes de recargar

Seguimos utilizando el mismo procedimiento:

editar → comprobar la sintaxis → recargar Apache → comprobar el resultado

Una directiva mal escrita o colocada en un contexto no permitido puede hacer que configtest devuelva un error.

4.5. Redirecciones sencillas​

Apache también puede indicar al navegador que un recurso o una URL debe solicitarse en otra dirección.

Para una redirección sencilla podemos utilizar la directiva Redirect, proporcionada por mod_alias.

Por ejemplo, si hemos cambiado la ubicación de una sección:

Redirect permanent "/antigua/" "/nueva/"

Cuando el cliente solicite:

http://www.empresa1.test/antigua/

Apache responderá indicando que debe utilizar:

http://www.empresa1.test/nueva/

Redirecciones temporales y permanentes​

La palabra permanent indica una redirección permanente, asociada al código HTTP 301.

Para una redirección temporal podemos utilizar:

Redirect temp "/mantenimiento/" "/"

que utiliza el código 302.

en este ejemplo

No necesitamos aprender todavía mod_rewrite para realizar este tipo de redirecciones.

Cuando solo queremos enviar una URL a otra, Redirect resulta suficiente. mod_rewrite se reserva para reglas de reescritura más complejas.

Comprobar la configuración​

Después de modificar el VirtualHost:

sudo apache2ctl configtest

Si obtenemos:

Syntax OK

recargamos Apache:

sudo systemctl reload apache2

Y comprobamos desde el navegador la URL antigua.

Idea clave

Una redirección no entrega directamente el contenido de la nueva URL.

Apache informa al cliente de que debe realizar la petición en otra dirección y el navegador realiza esa nueva petición.

4.6. Qué es un módulo de Apache​

Apache está diseñado de forma modular.

Esto significa que determinadas funcionalidades son proporcionadas por componentes que pueden incorporarse al servidor según sean necesarios.

Por ejemplo:

Funcionalidad o directivaMódulo relacionado
DirectoryIndexmod_dir.
Listado automático de directoriosmod_autoindex.
Directiva Headermod_headers.
Autorización mediante Requiremod_authz_core.
Autenticación Basicmod_auth_basic.
HTTPS/TLSmod_ssl.

No necesitamos estudiar todos los módulos.

Lo importante es comprender que una directiva puede depender de que el módulo que la proporciona esté cargado.

4.7. Comprobar qué módulos están cargados​

Apache puede mostrar los módulos que tiene cargados mediante:

sudo apache2ctl -M

La salida será similar a:

en este ejemplo

El nombre mostrado por apache2ctl -M puede no coincidir exactamente con el nombre utilizado en la documentación.

Por ejemplo:

  • La documentación habla de mod_dir.
  • En la salida podemos encontrar dir_module.

Lo importante es identificar qué funcionalidad corresponde a cada módulo.

Podemos buscar uno concreto:

sudo apache2ctl -M | grep dir

4.8. Módulos disponibles y módulos habilitados en Debian​

Debian organiza los módulos de Apache de una forma parecida a los sitios virtuales que ya hemos utilizado.

Los módulos disponibles se encuentran en:

/etc/apache2/mods-available/

Los módulos habilitados aparecen en:

/etc/apache2/mods-enabled/

Podemos comprobar ambos directorios:

ls /etc/apache2/mods-available/

y:

ls -l /etc/apache2/mods-enabled/

En mods-available encontraremos archivos como:

No todos los módulos necesitan necesariamente los dos archivos.

  • Los archivos .load contienen la información necesaria para cargar el módulo.
  • Algunos módulos disponen además de un archivo .conf con configuración asociada.

Cuando un módulo está habilitado, Debian crea en mods-enabled los enlaces necesarios hacia sus archivos de mods-available.

Es el mismo patrón que ya conocemos

Con los sitios utilizamos:

sites-available → sites-enabled

Con los módulos encontramos:

mods-available → mods-enabled

No necesitamos crear esos enlaces manualmente. Debian proporciona herramientas para hacerlo.

4.9. Habilitar y deshabilitar módulos​

Para habilitar un módulo utilizamos:

sudo a2enmod nombre_modulo

Por ejemplo, cuando necesitemos el módulo headers:

sudo a2enmod headers

Después debemos comprobar y aplicar la configuración:

sudo apache2ctl configtest
sudo systemctl reload apache2

Para deshabilitar un módulo utilizamos:

sudo a2dismod nombre_modulo

Por ejemplo:

sudo a2dismod headers

Y volvemos a comprobar y recargar:

sudo apache2ctl configtest
sudo systemctl reload apache2
No deshabilites módulos al azar

Algunos módulos son necesarios para funciones que ya está utilizando Apache y otros módulos pueden depender de ellos.

Utilizaremos a2enmod o a2dismod únicamente cuando una configuración concreta lo requiera.

Durante los próximos apartados necesitaremos módulos relacionados con autenticación, autorización y HTTPS.

4.10. Relación entre una directiva y su módulo​

Comprender la relación entre directivas y módulos nos ayuda también a interpretar errores.

Supongamos que añadimos una directiva y al comprobar la configuración obtenemos un mensaje similar a:

Invalid command 'Header', perhaps misspelled or defined by a module not included in the server configuration

No debemos empezar a cambiar archivos al azar.

Podemos seguir este procedimiento.

1. Consultar la directiva​

Buscamos Header en la documentación oficial.

Comprobamos que pertenece a:

mod_headers

2. Comprobar si está cargado​

sudo apache2ctl -M | grep headers

Si no aparece ningún resultado, comprobamos si el módulo está disponible:

ls /etc/apache2/mods-available/headers*

3. Habilitarlo si realmente lo necesitamos​

sudo a2enmod headers

4. Volver a comprobar​

sudo apache2ctl configtest

Y, si la configuración es correcta:

sudo systemctl reload apache2
Diagnóstico antes de modificar

Cuando Apache indique que no reconoce una directiva, debemos comprobar al menos:

  1. Si el nombre está correctamente escrito.
  2. Si la directiva puede utilizarse en ese contexto.
  3. Qué módulo proporciona la directiva.
  4. Si ese módulo está cargado.

Este procedimiento será especialmente útil en los siguientes apartados, donde utilizaremos funcionalidades de autenticación, autorización y HTTPS.

4.11. Para comprobar que lo has entendido​

Antes de continuar

Comprueba que puedes:

  1. Explicar qué es una directiva de Apache.
  2. Diferenciar una directiva de un comando de Linux.
  3. Explicar por qué una directiva no puede utilizarse necesariamente en cualquier lugar.
  4. Reconocer los contextos de servidor, host virtual, directorio y .htaccess.
  5. Consultar la documentación oficial de una directiva.
  6. Identificar en esa documentación su sintaxis, contexto y módulo.
  7. Utilizar DirectoryIndex y Options -Indexes dentro de un bloque <Directory>.
  8. Explicar qué es un módulo de Apache.
  9. Comprobar los módulos cargados mediante apache2ctl -M.
  10. Diferenciar mods-available de mods-enabled.
  11. Explicar para qué sirven a2enmod y a2dismod.
  12. Relacionar un error de directiva desconocida con el módulo que la proporciona.
